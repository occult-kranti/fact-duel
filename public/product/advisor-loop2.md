## Assessment

The implementation meaningfully extends the product. A first visitor can start an untimed three-card Discovery session, retain sourced explanations, earn finite local activity points and cosmetic finishes, and revisit facts in the Vault. Stable fact IDs reach the client only when a duel result is revealed; a separate passport preserves earned counts beyond rolling journal limits. IndexedDB transactions serialize writes. The decorative Three.js scene is explicit opt-in, defaults to static artwork, and is absent from room rendering. Competitive rules and cosmetics remain separate.

The first snapshot had two P0 and four P1 findings. Targeted reinspection confirms queued exports, clock-independent seat generations, frozen recall decks, corrected mission routing, accurate untimed-attempt labels and restored touch targets. A further P0 recovery edge and P1 in-flight generation edge were identified, repaired and reinspected. **No concrete source-level blocker remains in the reviewed overhaul paths.** This conclusion does not close the empirical pilot gates or the separately pending Studio evidence review. Final status is listed below; the original findings are retained as review history.

## Loop 1 criteria supported by current source

- **Durable earned activity:** stable-ID facts and per-fact booleans make repeat room snapshots, explanation opens and untimed attempts idempotent. Passport facts are separate from the 200-round/100-match history windows. The finite ledger limit is 1,200 IDs; current content has 54 questions.
- **Migration and reset scope:** the old journal migrates into IndexedDB without retroactively inventing stable IDs or activity points. Existing records remain readable. Reset explicitly names journal, saved facts, missions, points and cosmetic finishes, while retaining theme/sound. A reset stored in IndexedDB prevents the old localStorage journal from remigrating on later reads.
- **Cross-tab persistence:** one read-write transaction performs read/reduce/write. BroadcastChannel and window-focus refresh re-read authoritative local state. The in-memory fallback visibly states that new activity lasts for the visit. This supports browser-local persistence, not accounts or globally verified progress.
- **Finite missions and cosmetics:** rewards are deterministic, fixed card finishes. No streak loss, timer bonuses, paid advantage, answer unlocks or room-coin effects are present. Complete missions stop asking for further progress.
- **Fresh untimed entry:** Discovery requests three open teaching cards from the same sample, has no clock or opponent, keeps one choice per card, exposes explanation/source after the choice, and offers a session ending. The UI explicitly discloses that these cards share facts with the duel sample.
- **3D containment:** static art is default. The scene loads only after an explicit action. DPR is capped at 1.25; shadow map is 512; continuous rotation is opt-in and throttled to 30fps; hidden/offscreen scenes stop rendering. Disposal cancels frames, removes listeners/observers, and frees WebGL resources. An abort check after the dynamic import prevents late renderer creation following unmount. Room rendering contains no ArcadeStage.
- **Click-release contract:** answer buttons use ordinary click activation; 1–4 keypresses remain. Elapsed time is captured at activation, first answer locks, retries retain the same payload, timed cards do not move, and rules describe the changed contract. The statement that swiping does not answer still needs actual touch validation across supported browsers; source inspection alone cannot establish physical input behavior.
- **Mobile hierarchy:** source order places welcome and match builder before showcase; the narrow layout is one column. The CTA appears before advanced settings and art. Navigation has five named destinations, and active matches retain mute/leave while hiding side navigation.
