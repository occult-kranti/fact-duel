# FACT//DUEL Curiosity Arcade — advisor loop 1

Date: 12 September 2026. Independent source review only. Inspected the current Arena, Journal, Collections, global styles, room engine, question catalogue, journal tests, Studio, and release roadmap. No Site edits, browser session, physical phone, assistive-technology session, performance measurement, or WAN validation was performed. The findings below concern actual source behavior and proposed implementation risks; they are not customer-study findings.

## Direction

Proceed with the warm cream/ink, coral/yellow, dark-plum Curiosity Arcade direction. Tactile artifacts fit a product in which a short duel leaves a sourced fact behind. The strongest game loop is **choose a curiosity → play voluntarily → inspect the explanation → collect the fact → revisit it without a timer**. Missions and cosmetics should recognize that loop. A new scoreboard, more counters, or a moving homepage alone would not address the existing product's shallow fact depth or demonstrate retention.

Keep direct play, collection browsing, and recall as peer entry points. A new visitor should see a usable free-practice action before a wall of progression panels. An existing visitor should see one next useful action, the reason it matters, and a natural stopping point. Keep the random bot, private friend access, three modes, room-scoped demo coins, and untimed recall legible in the new vocabulary.

## Prioritized acceptance criteria

| ID | Priority | Finding / risk | Bounded acceptance criteria |
|---|---|---|---|
| A01 | P0 | **Progress can regress at retention caps.** `lib/journal.mjs` retains 200 rounds and 100 matches. Totals derived directly from these arrays are recent/retained history, not lifetime earned progress. With enough repetition, previously encountered topics can disappear. | Either maintain a separately validated earned-progress record with idempotent awards, or explicitly label progress as retained-history activity. A sequence of 220 completed matches cannot silently revoke advertised lifetime levels, earned cosmetics, or completed missions. Tests cover the cap boundary and repeated snapshots. Do not grant completion credit to cancelled/refunded matches. |
| A02 | P0 | **Fact identity is currently text-based.** `uniqueFacts()` keys by question text. The server bank has stable `q001`-style IDs, but `projection().question.id` is the round ID, and the public catalogue has no question IDs. Reworded facts can double-count and different facts with identical prompts can collapse. | Prefer exposing a stable fact identity only with the result and persisting it alongside round identity. Define migration for existing journal items. Passport counts must deduplicate a fact across rooms, opponents, answer shuffles, and replays. Encountering is distinct from answering correctly or mastering. If stable IDs are deferred, copy must state the text-based sample limitation and avoid an exact coverage promise. |
| A03 | P0 | **Recall XP is easy to inflate unintentionally.** Existing recall only stores transient choice/index; repeat sessions are unlimited and reveal the answer immediately. A callback in an effect or every button click can award the same fact repeatedly. | Define an award event with a stable fact key and an explicit frequency. Recommended initial contract: first attempted untimed recall per fact gives activity credit; correctness is feedback, not a claim of durable learning. Rendering, back/forward, finishing practice, double-clicks, replaying the same card, and reloading cannot independently multiply that event. Preserve wrong-answer feedback and the source. |
| A04 | P0 | **New local state changes the deletion/export contract.** Settings currently promise to clear match history and saved facts only. Local-storage writes can fail; concurrent tabs can overwrite journals. | Name precisely whether clear removes journal, recall activity, missions, earned progress and cosmetic choice. Reset all included keys/state atomically at the application level; locked cosmetics cannot remain equipped after a reset. Export contains the state users are asked to preserve. No first-render write overwrites loaded state. Malformed/unknown versions, numeric bounds and missing fields safely fall back. Keep one-tab and visit-only storage limitations visible where relevant. |
| A05 | P0 | **3D work can interfere with timing.** Reveal currently uses two animation frames and `performance.now()`; server plausibility permits only a capped 0.5–2s transport envelope. CSS/JS load can consume that budget. | During scheduled/playing states no decorative animation, pointer tilt listener, continuous canvas/WebGL frame loop, particle effect or reward transition remains active. Timed question and answer controls stay geometrically still. Load essential play controls independently of visual assets. Reduced-motion preference produces a stable artifact without losing text or actions. A missing visual asset cannot block create/join/ready/answer. |
| A06 | P0 | **Touch commits on initial contact.** Arena uses `onPointerDown` with `preventDefault`; a scroll gesture starting on an answer can submit it. Pointer release is not currently cancellable. `onClick(detail===0)` and 1–4 support keyboard/assistive routes. | Preserve the current press rule, first-answer lock, immutable retry payload, keyboard shortcut and assistive click. Do not attach tilt/drag/hold behavior to timed answer cards. Keep the brief press disclosure. Ensure long content can be scrolled using space outside options. If changing touch cancellation, explicitly redesign when elapsed time is captured and test it; do not silently switch input timing. Physical touch testing remains a roadmap gate. |
| A07 | P0 | **Gamified missions can reward things the app cannot establish.** Local journal activity is editable and browser-specific; bot outcomes are random; a source link click does not establish that a source was read. | Label XP/levels as local activity or exploration, not verified skill, rank, mastery or intelligence. Give no duel time, answer, accuracy or coin advantage to cosmetics. Call a source-click mission “open a source,” not “verify a fact”; avoid rewarding that proxy if the click is not instrumented. Bot and friend counts stay distinguishable. No implied human opponent, streak loss, daily scarcity or automatic rematch. |
| A08 | P1 | **A collection passport may promise unavailable depth.** Nine current topics contain six sample questions each. Existing deck choice avoids repeats within a match only, not across rooms. | Numerator means distinct facts encountered; denominator comes from the matching catalogue topic. Empty and complete states have useful actions. Avoid “100% mastered” and guaranteed-new-card copy. Completion can offer recall or another collection. Bank version/removal behavior is declared if exact permanent completion is shown. Keep actual sample count and editorial difficulty visible. |
| A09 | P1 | **Expanded navigation can bury first play or disable necessary exits.** Current active matches hide side navigation and prevent in-app routing. Internal tabs do not use URL history. New missions/passport/cosmetics may add competing destinations. | At 320–430px widths, the main practice CTA and chosen mode are not preceded by a tall 3D hero plus several progress panels. Navigation remains named, reachable, and gives visible current state. Every new reward/mission CTA navigates to an executable state rather than a dead-end badge. Active matches retain mute and explicit leave; settled matches offer both play and journal. Selection of a collection resets incompatible region/difficulty/subtopic filters. Document browser-history limitations if unchanged. |
| A10 | P1 | **Tactile shadows and colored panels can hide control boundaries.** Existing styles depend on semantic foreground/background/border variables; dark/light Studio inherits globals. | Check normal, selected, focus, disabled, loading, error and correct-answer variants in both themes. Text uses at least 4.5:1 for ordinary text / 3:1 for large text; essential control boundaries/focus states have sufficient contrast. Information is also carried by text/icon/pressed state. All tappable primary controls remain at least 44px. Decorative overflow cannot cause horizontal page scrolling. |
| A11 | P1 | **Studio can contradict the redesigned site.** Existing Studio describes navy/cobalt, a knowledge club, 40 issues, 29 sources and previous two critique loops. P33 treats a voluntary weekly ritual as blocked. | Update current decision prose, implementation evidence, source/issue counts and visible release vocabulary together. Preserve earlier reviews as historical evidence. Mark new design/progression work as implemented only after source/tests support it; keep observed mobile, assistive, first-session, WAN, consented analytics and retention gates unobserved until actual evidence exists. Avoid claiming the new design fixes real customer behavior before observation. |

## Minimal regression checklist for loop 2

1. Run existing engine/HTTP/bot/journal tests plus focused tests for the new progression contract: duplicate snapshot, repeat fact, repeat recall, cap boundary, corrupt state, migration, cancelled match, and reset/reload. Add only tests tied to these concrete risks.
2. Inspect raw changed source for timed input guards, hidden visual loops, stable fact identity, reward idempotence, and accidental imports of the server answer bank into client code.
3. Confirm all three modes and 10/15/30-second durations remain supported; bot plans remain random and fixed before play; retry payloads and settlement rules do not change as a side effect of presentation work.
4. Validate the production build and TypeScript. Treat rendering checks as rendering evidence, not actual mobile or WAN evidence.
5. Reconcile new Studio decisions/roadmap with the implementation. Leave P15/P16/P18 and observed retention claims pending unless separately measured.

## Scope decisions that can be safely deferred

Cross-device accounts, remote analytics, globally authoritative XP, public leaderboards, scheduled missions and anti-cheat are unnecessary for this redesign. A disclosed browser-local exploration profile is enough. Complex 3D libraries are also unnecessary if a lightweight CSS artifact supplies depth and responds to the user while respecting reduced motion. Keeping those boundaries avoids building unearned authority into cosmetic progression.

No conclusion about actual customer satisfaction, accessibility conformance, phone performance, retention improvement, or WAN fairness is made by this review.
