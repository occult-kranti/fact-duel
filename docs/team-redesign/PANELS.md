## Review rounds

1. **Baseline → first implementation.** Research and architecture reviewed the existing source. The moderator chose a separate team authority, preserved solo play, assigned explicit file ownership and approved the mobile visual system. The first revised artifact includes team screens, new navigation, headers/captions, theme layer and editable design canvas. Server work is tracked independently until executable checks pass.
2. **Implementation challenge.** Reviewers inspected the changed screens and SQL. Corrective revisions fixed abandoned recruiting cups, expired challenge acceptance, whole-cup reconciliation, scoring copy, banner thresholds, consent-button gating, accessible confirmations, stale response ordering, scorecard/run separation and the primary action buried under an eleven-player roster. The canvas corrected a Window.top script-name collision and a desktop-to-mobile navigation target. These are revisions to the actual implementation, not repeated reports about an unchanged design.
3. **Verification and publication.** The revised candidate passed 1,092 tests with no failures or skips, TypeScript, static production build and Pages assembly. Fifteen PostgreSQL team cases include a fully played four-team cup with 90 accepted answers. The independent security reviewer ran four selected SQL checks. Browser reviews covered 320px and 390px iframe viewports plus a 1348px desktop view: entry, capacity selection, name preview, consent gating, day/night colours and navigation. No horizontal overflow was found in those selected views. Authenticated browser team play, physical-phone ergonomics and real-team satisfaction remain unverified.
