# Club identity and appearance integration

Club identity comes from current authenticated server projections. The additive `20261030040000_jhk_public_club_identity.sql` adds only `teamTag`, `teamName`, `teamPalette` and `teamSize` to self profiles, live match players, ranked board rows/self and savings board rows/self. Nonmembers, deleted members and archived clubs return null. It never returns invite codes, roles, membership IDs or permissions in public opponent projections. Nicknames, scoring, XP, answer release clocks, rotation and reactions remain unchanged.

The browser tracks a separate verified display snapshot with identity and server timestamp. Cached profile membership does not initially colour the game. Current profile/team replies verify it; older replies cannot restore a previous club after leaving. Recovery resets the snapshot to the recovered profile, forgetting clears it, and an expired/invalid credential removes club styling without creating another account. A late failure from a prior credential cannot clear a recovered profile. An authenticated own-team dashboard is supported as a compatibility fallback for a server lacking `teamPalette` on profile responses; public opponent teams cannot become the user's theme.

`lib/club-theme.mjs` exports the pure reducer, accent selection and `applyClubPalette(root, palette)`. The last function changes only `data-club-palette`. Existing Pavilion/Floodlights surfaces, motion and illustration choices remain separate. `Use club colours` is an explicit device preference, enabled initially, stored under the edition's namespaced `clubColours` key. Turning it off restores the default game accents while retaining the visible truthful club identity. Leaving removes club colours; joining/switching follows the newly verified club. Cross-device changes refresh on visible-page focus and every 30 seconds; transient connection failure retains the latest successfully verified snapshot.

The four palettes use contrast-safe filled controls and separate readable text tokens. Light: teal `#087F7A` with white; saffron `#FFBD59` with `#122C35`; berry `#8E3863` with white; blue `#285BB8` with white. Floodlights uses teal `#8CDBC9`, saffron `#FFCA7A`, berry `#ECAACD`, blue `#ADD3FF`, all with `#122C35`. `--club-accent-text` uses deeper variants on Pavilion. Semantic correct/error colours and answer surfaces are not remapped.

Executed checks: `tests/club-theme.test.mjs` runs 100 pure join/leave/switch/stale-identity/preference cycles plus 100 actual transport cycles (over 300 requests) and credential-expiry/recovery races, with no profile creation. The public SQL test applies its migration twice, compares exact pre/post function bodies after removing only display concatenations, and compares full timed Full over snapshots and leaderboards after removing the four new fields. It verifies current tags after leave/new club/recovery/archive, secrecy of invites and service-only access. Legacy team and new war SQL suites also load the new public projection migration. TypeScript passes with no diagnostics.
